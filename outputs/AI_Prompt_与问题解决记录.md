# AI Prompt 与问题解决记录

本文记录项目开发中使用的主要 AI Prompt、对应实现阶段、问题处理方式和验证结果。API Key 等凭证不写入本文件；供应商接入 Prompt 中的密钥已脱敏。

## 使用的主要 Prompt

### 项目边界与实施计划

> 请阅读项目现状和开发文档（Agent_Runtime_开发实施指南.md），确认现有技术栈与约定。不要使用 LangGraph、OpenHands、OpenClaw 或其他 Agent Runtime 框架。先给出与现有项目匹配的最小实现切片、需要新增/修改的文件和测试命令；暂不改代码。若仓库已有实现或用户改动，先说明并沿用，不要覆盖。

### 阶段 A：API 与数据层

> 按开发文档阶段 A 实现 API 骨架、SQLite 初始化、session/messages/todos 数据访问层及可替换的 LLMClient 协议。先确保测试不依赖真实模型或 API Key。完成后运行测试，并报告文件、接口和结果。

### 阶段 B：工具系统

> 按开发文档阶段 B 实现 Tool 定义、注册表、JSON Schema 参数校验，以及 calculator、mock search、持久化 todo（add/list/complete）。calculator 不得使用 eval。补充针对正常输入、非法参数、未知工具和 session 隔离的测试，然后运行测试。

### 阶段 C：Runtime 循环

> 按开发文档阶段 C 实现 response parser 和自研 AgentRuntime 循环：模型可直接回答或提出工具调用；Runtime 校验、执行、保存工具结果并继续调用模型；轮次和单轮工具数有限。用脚本化 fake LLM 覆盖直接回答、工具调用、连续调用、工具错误、无效响应和达到上限。不要接入 Agent 框架。

### 阶段 D：真实模型适配

> 阅读当前 LLMClient 和工具注册表，为项目配置的模型供应商增加适配器。供应商原生工具调用格式映射到 Runtime 内部统一类型；密钥从环境变量读取，不写入仓库。保留 fake LLM 测试，并给出本地配置方式。不要声称已完成真实模型验证，除非实际运行过。

### 阶段 E：追问与摘要压缩

> 按开发文档阶段 E 实现基于 session 的 context builder 和最基础摘要压缩：超过阈值时摘要较早对话、保留最近消息、历史原文仍持久化。确保模型请求不重复加入当前用户消息，摘要失败时不丢历史。补充纯对话追问、带工具追问、两个 session 隔离和重启恢复测试。

### 最终检查与测试

> 请对照 Agent_Runtime_开发实施指南.md 的验收清单检查实现，运行相关测试并做一次代码审查。优先报告会造成无限循环、跨 session 数据泄漏、任意代码执行、工具越权或历史丢失的问题；发现问题请直接修复并重新运行受影响测试。最后列出尚未实现的范围和真实模型验证所需条件。

## 问题与解决记录

| 问题/风险 | 处理方式 | 验证 |
| --- | --- | --- |
| Agent 若把控制流交给框架，无法验证工具边界和退出条件。 | 自行实现 `AgentRuntime`，由 Runtime 统一解析模型响应、校验并执行工具；不引入 Agent Runtime 框架。 | fake LLM 覆盖直接回答、工具调用、多轮、工具错误、无效响应和轮次上限。 |
| 计算器若使用 `eval` 可能执行任意表达式。 | 改为 Python AST 白名单，只允许数字、括号、加减乘除和正负号，并限制表达式长度与节点数。 | 测试正常运算、除零、函数调用和 Python 表达式拒绝。 |
| 用户的不同窗口可能串用消息或待办。 | 每个窗口创建独立 session；仓储操作与工具上下文均同时携带用户和 `session_id`。 | API 与仓储测试覆盖跨 session、跨用户访问拒绝及重启恢复。 |
| 工具调用结果若只存在进程内，后续追问和重启会丢失。 | 将 assistant 工具调用、tool 结果写入 SQLite `messages`，后续请求按 tool call ID 还原对话。 | 工具追问和数据库重建测试确认历史可恢复。 |
| 长历史导致上下文过长，摘要失败可能造成历史被截断。 | 超过 20 条历史消息时摘要较早部分，保留最近 10 条；摘要和原始消息分别存放，摘要失败回退到完整历史。 | 压缩、摘要失败保全、原文持久化及重启后恢复测试。 |
| API Key 可能被写入配置文件或日志。 | 从本机环境变量读取 `OPENAI_API_KEY`；OpenAI 兼容适配器只向请求头写入 Bearer 凭证；仓库示例仅包含占位符。 | 扫描项目文件未发现疑似 API Key；`.env` 在 `.gitignore` 中。 |
| 只用 fake LLM 无法证明供应商格式和账号可用。 | 配置 `deepseek-chat` 与 DeepSeek OpenAI 兼容端点，并保留 fake LLM 与 HTTP mock 测试。 | 真实 API 返回 `completed`；模型实际发起一次 `calculator` 工具调用，结果为 `48`，最终回复 `48`。 |

## 当前验证结果

- 自动化测试：`35 passed`；测试不依赖真实模型或 API Key。
- 在线验证：DeepSeek 真实 API 请求成功，并完成模型自主选择工具、Runtime 执行工具、结果回填和最终回复的完整路径。
- 当前限制：`search` 是 mock；开发身份固定为 `local-user`；没有向量检索或跨 session 长期记忆；真实账号的持续可用性取决于本机密钥状态、额度和网络。
